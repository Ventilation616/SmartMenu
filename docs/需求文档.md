# 料理配方管理 App 开发需求文档

&#x20;

**版本：V1.0**

## 一、项目概述

开发一款简单的个人料理配方管理 App，用于记录和管理料理配方。

软件的核心特点是：

> 编辑配方时，用户可以修改任意一个参与计算的食材用量，点击“保存”后，系统根据修改后的食材用量重新计算其他食材的用量。

每个食材可以单独设置：

- 是否参与比例计算
- 计算精度：`1g / 0.5g / 0.1g`
- 取整方式：`向上 / 向下`

软件主要用于个人及朋友小范围使用，不需要账号、服务器、社交等复杂功能。

# 十二、动态比例计算

假设原始配方：

食材

原始用量

鸡腿

500g

土豆

300g

生抽

30ml

白糖

15g

用户编辑时将鸡腿修改为：

```
800g
```

系统计算：

```
比例 = 新鸡腿用量 / 原鸡腿用量
```



&#x20;    \= 800 / 500



&#x20;    \= 1.6

然后计算其他食材：

```
土豆 = 300 × 1.6 = 480g
```



生抽 = 30 × 1.6 = 48ml



白糖 = 15 × 1.6 = 24g

最终保存：

```
鸡腿     800g
```

土豆     480g

生抽      48ml

白糖      24g

# 十四、如何判断哪个食材发生了比例变化

由于编辑页面允许用户修改多个字段，因此保存时需要判断：

> 哪个食材是本次动态调整的基准。

V1.0 建议采用简单规则：

### 规则

**同一时间只允许修改一个“参与比例计算”的食材用量作为比例基准。**

例如：

```
鸡腿 500g → 800g
```

允许。

系统自动计算：

```
土豆
```

生抽

白糖

但不允许用户同时手动修改：

```
鸡腿 500g → 800g
```

土豆 300g → 500g

因为此时系统无法判断：

> 土豆的 500g 是用户手动输入的结果，还是应该由鸡腿 800g 自动计算得到的结果。

因此需要明确：

> **编辑页面中，用户修改一个参与比例计算的食材用量后，其他参与计算的食材用量由系统自动计算。**

# 二十七、核心计算算法

伪代码：

```
saveRecipe(originalRecipe, editedRecipe):
```



&#x20;   target = 获取调整基准食材



&#x20;   if target存在:



&#x20;       scale =

&#x20;           target.newAmount /

&#x20;           target.originalAmount



&#x20;       for ingredient in editedRecipe.ingredients:



&#x20;           if ingredient == target:

&#x20;               continue



&#x20;           if ingredient.scalable == false:

&#x20;               continue



&#x20;           rawAmount =

&#x20;               originalAmount \* scale



&#x20;           newAmount =

&#x20;               applyRounding(

&#x20;                   rawAmount,

&#x20;                   ingredient.precision,

&#x20;                   ingredient.roundingMode

&#x20;               )



&#x20;           ingredient.amount = newAmount



&#x20;   validate(editedRecipe)



&#x20;   save(editedRecipe)

# 二十八、精度计算

精度为：

```
1
```

0.5

0.1

统一使用：

```
向下：
```



floor(amount / precision) × precision



向上：



ceil(amount / precision) × precision

例如：

```
amount = 10.76
```

precision = 0.5

向下：

```
floor(10.76 / 0.5) × 0.5
```

\= 10.5

向上：

```
ceil(10.76 / 0.5) × 0.5
```

\= 11

# 二十九、浮点数处理

计算过程中不能因为显示问题提前进行四舍五入。

例如：

```
5 × 1.3333333
```

应保留计算精度。

最后一步才根据：

```
precision
```

rounding\_mode

得到最终结果。

建议程序内部使用高精度 Decimal 计算，避免浮点数产生：

```
0.1 + 0.2 = 0.30000000000000004
```

之类的问题。
