# SmartMenu V1.0 开发任务拆分

本文基于 `docs/需求文档.md` 与 `docs/技术栈规范文档.md` 拆分，目标是把需求落成可执行、可排期、可验收的开发任务。

## 一、拆分原则

- 只覆盖 V1.0 范围内功能
- 任务按推荐开发顺序排列
- 每个任务尽量对应单一交付结果
- 核心业务规则优先落在 domain/use case，而不是 UI

## 二、里程碑划分

- T02 建立分层目录与基础应用骨架

## 三、详细任务清单

### T01 初始化 Flutter 工程与基础依赖

**目标**

搭建可运行的 Flutter 项目，并接入文档指定技术栈。

**工作内容**

- 创建 Flutter 工程
- 配置 `pubspec.yaml`
- 引入 `flutter_riverpod`、`drift`、`sqlite3_flutter_libs`、`freezed_annotation`、`decimal`、`go_router`、`logger` 等依赖
- 配置 `build_runner`、`drift_dev`、`freezed`、`json_serializable`

**交付物**

- `pubspec.yaml`
- 默认可运行的 Flutter App

**验收标准**

- `flutter pub get` 成功
- 工程可在本地启动
- 依赖版本与技术栈文档一致或兼容

### T02 建立分层目录与基础应用骨架

**目标**

建立与技术栈文档一致的目录结构，避免后续逻辑堆积在 UI 层。

**工作内容**

- 创建 `lib/app`
- 创建 `lib/core`
- 创建 `lib/domain`
- 创建 `lib/data`
- 创建 `lib/presentation`
- 创建基础空目录与占位文件

**交付物**

- 分层目录结构
- `main.dart`
- `app/app.dart`

**验收标准**

- 目录结构与技术栈文档一致
- 应用入口可正常编译

### T03 配置代码生成、Lint 与基础开发脚本

**目标**

补齐后续开发依赖的基础设施。

**工作内容**

- 配置分析规则
- 配置 `build_runner` 生成命令
- 配置 Drift / Freezed 代码生成所需文件
- 补充 README 中的本地开发命令

**交付物**

- `analysis_options.yaml`
- 基础生成配置
- README 开发说明

**验收标准**

- `dart run build_runner build` 可执行
- `flutter analyze` 无阻塞性错误

### T04 定义领域模型与值对象

**目标**

建立纯 Dart 领域模型，承载配方、食材、步骤和枚举规则。

**工作内容**

- 定义 `Recipe`
- 定义 `Ingredient`
- 定义 `CookingStep`
- 定义枚举/值对象：
  - `IngredientUnit`
  - `IngredientType`
  - `PrecisionOption`
  - `RoundingMode`
- 金额/用量相关字段统一采用 `Decimal`

**交付物**

- `domain/models/*`
- `domain/value_objects/*`

**验收标准**

- 模型支持不可变拷贝
- 模型字段能覆盖需求文档中的数据结构
- 不依赖 Flutter UI

### T05 设计 Drift 表结构与本地数据库

**目标**

完成本地数据库落库结构设计。

**工作内容**

- 定义 `recipes` 表
- 定义 `ingredients` 表
- 定义 `cooking_steps` 表
- 设计外键与级联删除
- Decimal 字段以 `TEXT` 保存字符串值

**交付物**

- `data/datasources/local/database.dart`
- `data/datasources/local/tables/*`

**验收标准**

- 表结构覆盖需求文档第二十二章
- 食材与步骤能按 `recipe_id` 关联
- 删除配方时关联数据一并删除

### T06 实现 DAO 与仓储

**目标**

为页面和用例提供统一数据访问接口。

**工作内容**

- 实现配方查询 DAO
- 实现食材与步骤 DAO
- 实现仓储接口与仓储实现
- 封装事务写入：配方、食材、步骤一次性提交

**交付物**

- `data/datasources/local/daos/*`
- `domain/repositories/*`
- `data/repositories/*`

**验收标准**

- 支持新增、详情查询、列表查询、更新、删除、搜索
- 写操作全部在事务内完成

### T07 实现 Decimal 精度与取整工具

**目标**

抽离核心数值规则，作为比例计算基础能力。

**工作内容**

- 封装 Decimal 字符串解析
- 实现精度处理工具
- 实现向上/向下取整算法
- 统一格式化输出规则

**交付物**

- `core/utils/decimal_utils.dart`
- `core/utils/rounding_utils.dart`

**验收标准**

- 支持 `1`、`0.5`、`0.1` 三种精度
- 不使用 `double` 进行核心乘除
- 示例 `10.76 + 0.5 + 向下/向上` 结果符合需求文档

### T08 实现配方校验规则

**目标**

在保存前统一执行业务校验。

**工作内容**

- 校验菜名不能为空
- 校验食材名称不能为空
- 校验数值用量必须为合法非负数字
- 校验基准食材必须可参与比例计算且原始用量大于 0
- 校验同一时间只能有一个比例调整基准

**交付物**

- `core/validators/*`
- `core/exceptions/*`

**验收标准**

- 新建与编辑保存均可复用校验逻辑
- 非法数据能返回明确错误信息

### T09 实现新建配方用例

**目标**

完成“新建只保存原始基准数据，不做动态计算”的业务流程。

**工作内容**

- 实现新建配方用例
- 保存基础信息、食材、步骤
- 处理“适量/少许/若干”等默认不可计算逻辑

**交付物**

- `domain/use_cases/create_recipe_use_case.dart`

**验收标准**

- 点击确认时只做校验和保存
- 不触发比例计算
- 点击取消不会写入任何数据

### T10 实现编辑配方保存时的动态比例计算用例

**目标**

实现本项目最核心的业务逻辑。

**工作内容**

- 进入编辑页时保留原始快照
- 根据原始数据与编辑副本识别调整基准
- 计算比例 `newAmount / originalAmount`
- 对其他 `scalable = true` 食材按原始值重新计算
- 按食材精度和取整方式处理结果
- `scalable = false` 食材保持原值
- 保存最终配方到数据库

**交付物**

- `domain/use_cases/update_recipe_use_case.dart`
- 必要的领域服务或计算器

**验收标准**

- 只允许一个可计算食材作为基准
- 保存时才执行重算
- 取消编辑时不写库
- 计算结果与需求文档示例一致

## 四、推荐开发顺序

建议按以下顺序推进：

1. T01-T03：先把工程跑起来
2. T04-T08：先固化模型、数据库和核心规则
3. T09-T11：先把用例打通
4. T12-T17：再接页面与交互
5. T18-T20：最后做测试、联调和文档

## 六、风险与注意事项

- 动态比例计算必须基于“编辑前原始快照”，不能基于编辑中的中间值连续累算
- Decimal 计算与显示格式要分离，避免因展示提前丢失精度
- 编辑页必须明确“谁是调整基准”，否则容易出现多食材同时手改导致规则冲突
- 数据库存储与领域模型之间需要明确 Decimal 字符串转换
- 写库必须走事务，避免配方、食材、步骤部分成功
